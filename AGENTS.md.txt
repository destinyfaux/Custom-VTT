1. Project Philosophy & Core Invariants

The VTT is designed as a digital tabletop, not a video game engine. It automates
math, line-of-sight geometry, particle dynamics, and network synchronization
while preserving human judgment and tabletop agency (dice rolling, narrative
decisions, and DM discretion).

Non-Negotiable Core Invariants

1.  Server as the Single Source of Truth: VTTManager.js holds the authoritative
    game state tree and persistence contracts. Clients send user intents; the
    server validates authorization, checks payload boundaries, mutates state,
    and emits events.
2.  Targeted Events Over Broadcast Storms: High-frequency, atomic mutations
    (e.g., token_moved, light_added, turn_update) must emit lightweight,
    targeted socket payloads. Never emit a full state_update unless performing a
    scene reset (change_map) or answering an explicit resync request
    (init_state, request_full_state).
3.  Non-Blocking Asynchronous Disk I/O: Never execute fs.writeFileSync in
    runtime request/socket paths. Persistence operations must use
    saveMapDataDebounced() (fs.promises.writeFile with a 500ms trailing
    debounce) or saveSession() (with explicit .flush()).
4.  Preserve Unplaced Tokens in Memory: Recalling a token (remove_token) sets
    isPlaced = false. Never filter/delete recalled tokens from canvas memory
    (tokens state array). Deleting unplaced tokens breaks Fog of War raycasting,
    wipes local avatar caches, and causes spawn failures.
5.  No Blind Full-State Overwrites on the Client: Components must update
    localized React state slices based on targeted events rather than relying on
    global full-state replacements.
6.  Zero-Lock Session Authentication: Authentication is identity-based via
    browser UUIDs stored in localStorage (vtt_user_id) and optional room codes.
    Never introduce mandatory external OAuth or relational database user account
    schemes.

3. Real-Time Socket Protocol & Event Matrix

Socket.IO is configured with transports: ['websocket'] and perMessageDeflate
(compression enabled above 1KB). All handlers pass through connection
rate-limiting middleware (socket.checkRateLimit(limit, windowMs)).

   [ Client Action ] ──► socket.emit('event', payload)
                                │
                                ▼
                       [ Socket.IO Server ]
                                │
                      Rate & Auth Validation
                                │
                                ▼
                       [ VTTManager.js ]
                     (State Mutation & _version++)
                                │
                                ▼
         ┌──────────────────────┴──────────────────────┐
         ▼                                             ▼
 [ Targeted Broadcast ]                       [ Debounced Disk Write ]
io.emit('token_hp_changed', { ... })         saveMapDataDebounced() (500ms)

4. Subsystem Deep Dives

4.1 Canvas Rendering Engine (CanvasMap.jsx)

  - Execution Model: Driven by requestAnimationFrame with delta-time throttling
    (locking animations to 60 FPS across high-refresh monitors).
  - Layer Rendering Order:
    1.  Background Table Texture (static image or 60 FPS looping HTML5 <video>).
    2.  Map Image (mapImage).
    3.  Decals & Stamps (stamps).
    4.  Ambient Day/Night Lighting overlay tint (clipped to map bounds).
    5.  Dynamic Fog of War (offscreen canvas fogCanvasRef clipped to player
        visibility + visible lights).
    6.  Grid lines (when showGrid === true).
    7.  Wall segments & Light source handles (DM edit mode only).
    8.  Rulers, Measurement Badges, Movement Trails.
    9.  Spell FX Particle Buffers (Particles, Missiles, Emitters).
    10. Active Tokens, Turn Pulse Rings, Condition Badges, HP Bars.
    11. Weather Parallax Dual-Layer Overlays (clipped to map bounds).
    12. Floating Ping Animations & DM Pushpins.

Fog of War Raycasting (VisibilityEngine.js)

  - Spatial wall hashing via buildWallGrid(walls, width, height).
  - Only player-controlled tokens (type === 'player' && isPlaced === true)
    generate base vision polygons.
  - Lights are hidden unless their coordinates fall within at least one player
    token's line-of-sight (pointInPolygon).
  - Critical Rule: When tokens move or are placed/recalled, visibilityData
    recalculates automatically. Keep token state pure.

4.2 Token Management & Tray Synchronization

  - Tokens exist in one of two states:
      - Unplaced (isPlaced: false): Displayed inside TokenTray.jsx stacked by
        name/avatar.
      - Placed (isPlaced: true): Positioned on CanvasMap.jsx at coordinates (x,
        y).
  - The Placement Flow:
    1.  DM clicks Spawn in TokenTray.jsx \rightarrow sets placingTokenId.
    2.  DM clicks coordinates on canvas \rightarrow CanvasMap snaps to grid step
        and emits move_token_final.
    3.  Server updates token.x, token.y, token.isPlaced = true and emits
        token_final_position.
    4.  CanvasMap upserts the token into its local state; TokenTray updates its
        unplaced filter.
  - The Recall Flow:
    1.  DM or owner right-clicks token \rightarrow clicks Recall \rightarrow
        emits remove_token.
    2.  Server sets token.isPlaced = false and emits token_removed.
    3.  CanvasMap updates token to isPlaced: false (hiding it from the field and
        removing its vision polygon).
    4.  TokenTray shows the token back in the unplaced list.

4.3 Combat, Death Saves & Vitality Pipeline

  - Round Tracking: `state.round` starts at 1 on `start_combat`, increments
    whenever a turn advance wraps from the last combatant back to the first,
    and resets to 0 on `reset_combat`. Broadcast in `combat_started` and
    `turn_update` payloads; persisted in room state JSON.
  - Player End Turn (S1): `end_turn` is the player-autonomy turn door — the
    active player passes initiative without a DM relay. Ownership is
    validated server-side (token.type === 'player' AND
    (token.ownerId === userId || token.id === userId), DM bypasses).

[ Damage Event: update_token_hp ]
                │
                ├─► Single hit >= Max HP at 0 HP ──► [ Instant Death (💀 Dead) ]
                │
                ├─► Damage while at 0 HP ──────────► [ +1 Death Save Failure ]
                │                                             │
                │                                    Failures + Wounds >= 3?
                │                                      ├── Yes ──► [ 💀 Dead ]
                │                                      └── No  ──► [ Maintain Downed ]
                │
                ├─► Damage >= 1/2 Max HP ──────────► [ System Shock: Massive Damage ]
                │                                      (Triggers CON Save Prompt)
                │
                └─► Downed for 3rd+ Time ──────────► [ System Shock: Excessive Damage ]
                                                       (DC = 15 + 3 * (timesDowned - 3))

  - Turn Start Check: turn_started checks if the current token is at 0 HP, not
    stable, and not dead. If true, it triggers onDeathSaveTrigger strictly on
    the token owner's client or DM client (avoiding global modal popups).
  - Rest Pipeline:
      - Short Rest: Prompts player for Hit Dice expenditure; heals token and
        updates character sheet.
      - Long Rest: Restores HP to max, resets deathSaveSuccesses,
        deathSaveFailures, timesDowned, clears isDead, and reclaims up to
        \lfloor \text{Total HD} / 2 \rfloor (minimum 1).

4.4 Spell FX System (FXEngine.js)

  - Limits: MAX_PARTICLES = 3000, MAX_MISSILES = 20, MAX_EMITTERS = 10.
  - Shapes: AOE, Cone, Beam, Missile, Burn, Glow, Slash, Smash, Pulse, Ring.
  - Styles: Fire, Water, Blood, Holy, Dark, Frost, Acid, Smoke, Slash Spark,
    Impact Dust, Lightning, Force.
  - Lifecycle: When a user casts, executeCastLocal() runs locally and
    socket.emit('cast_fx', ...) is broadcast to peers. The engine runs in a
    separate requestAnimationFrame loop on CanvasMap.

5. Critical Pitfalls & Agent Guardrails

| Trap                         | Root Cause                                                                            | Mandatory Pattern                                                                                       |
| :--------------------------- | :------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------ |
| **Variable Shadowing**       | Re-declaring `const token = ...` inside a block that already defined `token`.         | Rename destructured outputs explicitly (e.g., `const { token: updatedToken } = result;`).               |
| **Scope Re-Declaration**     | Re-extracting `const { userId } = socket.auth` inside nested socket callbacks.        | Use the connection-level `userId` inherited via lexical closure.                                        |
| **Canvas Mount Crash (TDZ)** | Declaring `const draw = useCallback(...)` below `useEffect` hooks that call `draw()`. | Declare all state, refs, and the `draw` function **before** any lifecycle `useEffect`.                  |
| **Video Memory Leaks**       | Leaving `<video>` elements active on canvas unmount or asset reload.                  | Call `.pause()`, set `.src = ""`, and call `.load()` during cleanup lifecycles.                         |
| **Socket Listener Churn**    | Passing inline callback functions to socket hooks with changing references.           | Wrap dynamic callbacks in persistent React refs (e.g., `onDeathSaveTriggerRef`).                        |
| **Version Gap Deadlock**     | Dropping `state_update` payloads when `_version` advances via targeted events.        | Always apply incoming state in `App.jsx` immediately; never lock updates behind a version delta filter. |
| **Synchronous Disk Stalls**  | Calling `fs.writeFileSync` inside map drawing / token update paths.                   | Always call `this.saveMapDataDebounced()` inside `VTTManager.js`.                                       |

6. Standard Patterns for Extending the System

Pattern A: Adding a New Targeted Action

1.  Server (server.js):
    socket.on('custom_action', (payload) => {

Pattern B: Creating a Floating UI Modal

Always utilize useDraggableResizable to avoid duplicating window drag and resize
logic:

import { useDraggableResizable } from '../hooks/useDraggableResizable';

export default function CustomModal({ onClose }) {
  const { pos, size, handleMouseDown, handleResizeDown } = useDraggableResizable(
    { x: 200, y: 150 },
    { w: 450, h: 550 },
    { w: 250, h: 250 }
  );

  return (
    <div
      className="fixed z-[1000] bg-bgPanel border border-accentGold rounded-lg shadow-2xl flex flex-col overflow-hidden"
      style={{ left: `${pos.x}px`, top: `${pos.y}px`, width: `${size.w}px`, height: `${size.h}px` }}
      onMouseDown={handleMouseDown}
    >
      <header className="bg-bgCard p-3 flex justify-between items-center cursor-move border-b border-borderDark shrink-0">
        <span className="text-accentGold font-bold text-xs uppercase tracking-wider">Custom Tool</span>
        <button onClick={onClose} className="text-textMuted hover:text-white">✕</button>
      </header>
      <div className="flex-1 p-3 overflow-y-auto bg-[#0b0c10]">
        {/* Content */}
      </div>
      <div className="absolute bottom-0 right-0 w-4 h-4 cursor-nwse-resize" onMouseDown={handleResizeDown} />
    </div>
  );
}

8. Agent Session Continuity (memory persistence protocol)

Agent workstation containers are periodically wiped; this repo is the only durable
memory. Therefore:

- BEFORE working: read AGENT_WORKLOG.md (repo root) — project facts, roadmap state,
  milestone commits, and the latest session entries.
- AFTER working: append a new entry to AGENT_WORKLOG.md (append-only, `---` separator,
  Task ID / Agent / Task / Work Log / Stage Summary), then commit and push together
  with your code changes so the log always travels with the code.
- For combat / turn-engine changes, run the live E2E contract test before reporting:
    VTT_ALLOW_LEGACY_DM=true node server/server.js
    node server/e2e_s1_socket_contract.js
  Expect 43/43 assertions (S1 turn matrix + S2 snapshot + S3 movement contract T12).
  The filename deliberately avoids the *.test.js suffix so
  `npm test` (node --test unit suite) is unaffected.
