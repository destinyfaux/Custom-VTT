Project Overview

A lightweight, web‑based Virtual Tabletop for Dungeons & Dragons 5th Edition.
Replaces physical maps, tokens, and character sheets while keeping the Dungeon
Master in control. Built for small to medium groups, with emphasis on ease of
use, visual clarity, and extensibility.

Key Principles:

  - Manual over automation – no auto‑damage calculation, no enforced turn order.
  - Server authority – Node.js backend as single source of truth.
  - Frictionless – no accounts, UUID‑based identification, optional room code.
  - SRD‑powered character creation & monster bestiary (334+ creatures).

Core Philosophy & Design Principles

1.  Digital Table, Not a Video Game – tools that enhance, not replace, human
    judgment.
2.  Clean, Dark UI – Tailwind dark/gold theme for low eye strain.
3.  Canvas for Map, React for UI – separation of concerns.
4.  Minimal Dependencies, Maximum Control – no heavy state management.
5.  Everything is a File – maps, tokens, stamps, handouts, music, SFX,
    pre‑mades, SRD, weather assets, table textures.

Architecture & Data Flow

5.1 Core Flow

  - Server holds game state (VTTManager singleton).
  - Clients send intents via Socket.IO.
  - Server validates, mutates state, broadcasts updates.

5.2 Weather System

  - DM selects weather type, volume, and play state via WeatherPicker.
  - Server stores state.weather (type, volume, isPlaying, lightningEnabled) and
    syncs it.
  - Client AudioPlayer loads/loops the sound and scales the channel volume using
    localVolumeRef (master slider scale).
  - Client CanvasMap applies a canvas clipping mask to map boundaries, rendering
    dual‑layered parallax scrolling weather overlays.
  - Optional secondary texture (secondary.png) adds an extra layer to break up
    tiling.
  - Lightning flashes can be toggled on, triggering random white flashes (10‑20s
    intervals) with procedural thunder sound.

5.3 Volumetric Weather Parallax & Physics

  - Dual‑Layer Render: Reuses a single loaded texture across two layers to
    eliminate tiling seams. Layer 1 (Foreground) renders at 1.0× scale and
    speed 1.7. Layer 2 (Background) renders at 1.35× scale and speed 0.65
    diagonal.
  - Wind Vector Integration:
      - Floating Weather (fog, ash_storm, fallback) drifts in organic cross‑wind
        vectors (opposite directions on the X‑axis).
      - Falling Weather (rain, snow, blizzard) slides down (positive Y) and
        drifts right (positive X) locked to a realistic 5‑degree tilt using the
        tangent scale factor (≈0.087).
  - Boundary Masking: Applied via a canvas clipping path (ctx.clip()) mapped to
    map coordinates (0, 0, mapImage.width, mapImage.height). The tabletop wood
    grain background remains clear of weather.

5.4 Dynamic Media Table Asset

  - The frontend queries /api/table-texture using a lightweight HEAD fetch.
  - If the header returned starts with video/, the frontend initializes a
    loop‑muted, inline HTML5 video element, sets isTableVideo = true to
    continuously repaint the canvas at 60 FPS, and draws active frames onto the
    canvas via ctx.drawImage().
  - If standard image formats are detected, isTableVideo = false and rendering
    remains on‑demand to conserve resources.

5.5 Socket Listener Stability & Ref Patterns

  - All socket listeners registered once (empty dependency array) using
    tokensRef to avoid stale closures.
  - Callback props (such as onDeathSaveTrigger) that re‑evaluate on every render
    are backed by persistent refs (onDeathSaveTriggerRef) to eliminate constant
    listener teardown and unregister/re‑register cycles.
  - Pings, token movements, HP changes, weather updates, FX casts, shapes,
    system shock, and death save events are never dropped.

5.6 State Versioning & Auto‑Resync

  - Every state_update carries a sequential _version. Clients track the last
    version and detect gaps.
  - On gap, they automatically emit request_full_state; server replies with
    init_state (full state).
  - A manual REFRESH button is available for all users in the ConnectionStatus
    panel.

5.7 Connection Lifecycle

1.  User opens page, enters name, room code (if set), chooses role.
2.  Client connects with UUID + role + roomCode in handshake.
3.  Server registers user, sends init_state, broadcasts player list.
4.  Character sheet data is immediately synced via sync_character_data.
5.  All subsequent changes are sent as intents, resulting in state_update
    broadcasts.

Key Modules & Components

6.1 Server (VTTManager.js & server.js)

  - Maintains state version counter; getGameState() attaches _version to every
    broadcast.
  - addNPCToken accepts monsterData to embed full SRD stat blocks.
  - HP sync: adjustTokenHP pushes updated HP back to player’s character sheet
    when token is a player.
  - Map persistence (saveSession) includes tokens with monsterData and hidden
    states, stamps, and shapes.
  - Dynamic endpoints: /api/weather lists weather directories,
    /api/table-texture serves any matching table texture file.
  - System Shock: Automatically detects massive, critical, and excessive damage
    on token HP changes. Fires socket notifications containing exact current HP
    metrics (hpCur) so clients can evaluate wound conditions.
  - Death Saves: Authoritatively updates and computes successes/failures. Resets
    trackers when HP returns above 0.
  - Shapes: Stores persistent area markers (circle, rectangle, cone, line) in
    map data.

6.2 Client (CanvasMap.jsx, AudioPlayer, WeatherPicker)

  - CanvasMap.jsx – stable socket listeners, 60 FPS animation throttling using
    delta‑time, parallax weather overlay, dynamic table background (including
    video), extended measuring tool (line, circle, cone, square) with
    pill‑shaped text badges, anchor handles, rotated text.
  - AudioPlayer.jsx – syncs music, SFX, and weather sounds. Weather loops scale
    with master volume slider.
  - WeatherPicker.jsx – draggable, resizable modal with error‑catching JSON
    parser, lightning toggle, and preview audio cleanup.

6.3 Canvas Engine & Visibility

  - VisibilityEngine.js – raycasting against walls generates visibility polygons
    for fog of war.
  - Hidden lights: point‑in‑polygon check ensures only lights visible to at
    least one player token illuminate the fog.
  - Right‑click token menu: Heal, Damage (all users), Conditions (DM only), View
    Stat Block (DM, for NPCs with monsterData).
  - Hide/Reveal tool (shortcut 7) toggles token/stamp visibility.
  - Measure tool (M key) and Ping tool (P key) with smooth animations.
  - Token movement throttled to 100ms, final position on mouseup.

6.4 Character Sheet Pop-out Modal (Option B)

  - Unified Dashboard pop-out: The core character sheet (👤 tab in Sidebar) has
    been converted from a sliding panel into a wide-aspect overlay modal
    (max-w-[1260px] h-[92vh]). Senses (SensesCard) has been integrated directly
    into this pop-out, eliminating the redundant eye (👁️) sidebar dock button.
  - Optimized 3-Column Grid:
      - Column 1 (Identity & Presets): Full character details header, photo
        avatar file uploader, JSON export/import utilities, and collapsible
        pre-made sheets browser.
      - Column 2 (Attributes & Senses): Side-by-side core stats (StatCard) on
        top of passive perception, investigation, and insight meters
        (SensesCard).
      - Column 3 (Combat & Vitality): Vitals (CombatCard - with manual, unlinked
        death save checkboxes completely removed) on top of the newly integrated
        Wounds, Debuffs, and automated Rest pipeline.
  - Adaptive Design: Sizing and tight padding blocks (p-4 to p-3) utilize
    vertically efficient bounds to completely avoid excessive scrollbars.
  - Sliding Drawers: Specialised sheets (Skills, Spells, Features, Feats,
    Appearance, and Journal) continue to open as quick-access sliding drawers,
    preserving horizontal battlefield view during combat.

  - Socket – add_shape and remove_shape events sync across clients.

6.10 System Shock, Wounds & Interconnected Rests

  - Massive Damage: Damage >= 1/2 max HP → DC 15 CON save or suffer 1 wound +
    d10 effect from Massive Damage table.
  - Critical Damage: Damage >= max HP → DC 15 CON save or suffer 1-2 wounds +
    d10 effect from Critical Damage table.
  - Excessive Damage: Downed for 3rd+ time since rest → DC 15+3*(timesDowned-3)
    CON save or suffer 1 wound.
  - Automated Drops to 0 HP: If a d10 table result dictates that the target
    drops to 0 hit points, the client dynamically checks their remaining HP
    (hpCur) and emits an automatic damage event with sender "System Shock
    Wound". This applies the precise remaining damage and logs the exact damage
    source and HP reduction to the global chat.
  - Wounds & Debuffs: Stack with death save failures. Apply debuffs (speed
    penalty, disadvantage, capped healing). Wounds are displayed on the sheet
    and can be cleared by the DM.
  - Interconnected Rests:
      - Short Rest: Prompts players to roll their available Hit Dice. Rolls
        1d[HitDie] + CON modifier (minimum 1) per die spent, updating character
        sheet values and emitting standard token healing socket events.
      - Long Rest: Heals the player to full, clears death saves/stables, resets
        downs, and authoritatively reclaims up to half of their total maximum
        Hit Dice (minimum of 1).

6.11 Automated Death Saves & Turn Tracking

  - Turn‑Triggered Prompts: At the start of a combat turn, if a token is at 0
    HP, is not stable, and is not dead, a DeathSaveModal prompts the player for
    a roll.
  - Ownership Validation: By matching the active player's ID with the token's
    owner, only the affected player sees the prompt on their screen (DM receives
    prompts for NPC tokens), preventing global modal spam.
  - Visual Glowing Indicators: An automated, non-interactable status panel in
    the character sheet displays death save progress using custom square
    indicators:
      - Successes (S): Emerald-green glowing filled boxes.
      - Failures (F): Crimson-red glowing filled boxes.
  - Critical Rolls:
      - Natural 20: Immediately regains 1 HP, stands back up, and clears all
        death save progress.
      - Natural 1: Counts as 2 failures.
  - Damage at 0 HP: Taking any damage while at 0 HP counts as 1 failure. If a
    single damage source equals or exceeds the token's Max HP, they suffer
    Instant Death (sets current HP to 0, sets status as dead, and applies the
    "Dead" condition, represented on the map by a skull badge 💀).

Pitfalls, Lessons Learned & Debugging

Hoisting & React's Temporal Dead Zone (TDZ): Declaring const draw =
useCallback(...) below useEffect hooks that include draw in their dependency
list causes a fatal mount crash. All state hooks, references, selectors, and
core canvas drawing routines must be declared before any lifecycle triggers.

Display Refresh‑Rate Discrepancy: Standard requestAnimationFrame loops run at
the monitor's refresh rate. An animation designed for 60Hz will move 4× faster
on a 240Hz monitor. Throttling frame‑ticks using millisecond deltas (timestamp -
lastTime >= 16.67ms) is necessary to lock animation speeds.

404 Fetch Responses and JSON Errors: When fetching directory list data from a
missing or unconfigured API route, standard Express routers return HTML
templates (<!DOCTYPE html>). Parsing this with r.json() throws syntax errors due
to the leading <. Fallbacks must inspect the response's content‑type header.

Memory Leaks from Active Streams: Creating video elements on canvas mount
without unloading them when the component unmounts leaves video buffers running
in the browser's background, leading to CPU lag. Elements must be paused and
have their sources nullified on unmount.

React Prop Recreation causing Socket Churn: Passing transient, inline handlers
(such as onDeathSaveTrigger) to components that register WebSocket listener
hooks triggers continuous listener teardown and re‑registration on every minor
state update. Storing callbacks in persistent React Refs (onDeathSaveTriggerRef)
resolves this, preventing stale closures while keeping continuous socket uptime.

Ping unreliability: Socket listeners re‑registered on every tokens change,
creating a window where events were lost. Fixed by moving listeners to an
empty‑deps useEffect and using tokensRef.

Audio overlapping: multiple state_update broadcasts caused music to restart.
Fixed by only changing src when track URL actually differs.

Token move packet storms: throttled to 100ms, with final precise position on
mouseup.

Lighting revealed hidden rooms: clipped each light to player visibility polygons
using point‑in‑polygon test.

Stamp placement persistence: fixed by saving all tokens (including unplaced) and
calling saveMapData() after avatar changes.

State desync across continents: missing state_update packets caused stale maps.
Solution: state version numbers and automatic full‑state resync, plus manual
refresh button.

WebSocket transport forced to websocket only: prevented initial handshake. Fix:
revert to default ['polling', 'websocket'] to allow upgrade.

Invalid hook calls in AudioPlayer and App.jsx: useRef was placed inside
useEffect callback. Fix: move all hooks to top level of component.

drawRef pattern for weather: Weather textures were reloading on every drag frame
because draw was in the dependency array. Fixed by using drawRef and removing
draw from useEffect dependencies.

Secondary texture panning: Speeds were per‑frame, not per‑second. Fixed by
multiplying by 60 for delta‑time animation.

FX tool panning conflict: FX tool now sets tool='fx' and panning condition
excludes tool === 'fx'.

Particle system performance: Optimized by using refs instead of state for
particle arrays, and by using a separate animation loop for FX updates.

Shape tool deletion: Right‑click only deletes shapes when shape tool is active,
preserving context menu for tokens.

System Shock integration: Wounds and debuffs are now applied to character data
and synced to server. Death saves reset on healing. Excessive damage scaling
implemented.

Setup & Deployment

9.1 Local Development

  - Node.js v18+
  - cd server && npm install
  - cd ../client && npm install
  - Run start-vtt.bat or manually node server/server.js and npm run dev in
    client.
  - Open http://localhost:5173.

9.2 Adding Weather Assets

  - Create server/assets/weather/{type}/overlay.png (seamless, 512×512
    recommended).
  - Add server/assets/weather/{type}/sound.mp3 (looping).
  - Optional: add server/assets/weather/{type}/secondary.png for enhanced
    visuals.
  - Weather type appears in picker automatically.

9.3 Changing the Table Background

  - Upload any file named table-texture.* (e.g., table-texture.jpg or an
    animated table-texture.mp4) into server/assets/. The server handles
    extension detection.

9.4 Remote Play

  - Auto‑IP script updates client/.env (run npm run predev or included in start
    script).
  - Port forward 3001 (server) and 5173 (client).
  - Share http://<public-ip>:5173.
  - Optional: set VTT_ROOM_CODE environment variable.

9.5 Security Notes

  - Room code prevents unauthorised connections.
  - Basic payload validation (chat, notes, HP amounts).
  - No third‑party services; traffic stays within local network/forwarded ports.

Usage Guide

10.1 Player Quick Start

  - Login, choose role, enter room code (if any).
  - Character sheet → pre‑made or manual creation.
  - Use 👤 (Character Sheet tab) to launch your widescreen attributes, vitality,
    and passive senses dashboard modal.
  - Use 📋, ⚔️, ⭐, 🏆, 🧙🏻‍♂️, 🧬, 📖 tabs to quickly reference skills, class
    actions, spell lists, or journal logs in quick-access sliding panels.
  - Use 📏 (M) to measure (right‑click to cycle modes).
  - Use 📍 (P) to ping (color chosen in settings).
  - Use ✨ (F) to open the Spell FX tool – select a shape and style, then
    click‑drag on the map to cast visual effects.
  - Use ⬡ (Shape Tool) to place persistent area markers (circle, rectangle,
    cone, line) – right‑click to delete when shape tool is active.
  - Right‑click tokens to heal/damage.
  - Right‑click spells to prepare/unprepare.
  - Volume slider appears after first click anywhere (auto‑unlock).
  - Monitor connection health at bottom‑right status bar; click REFRESH if sync
    is out.
  - When at 0 HP at the start of your turn, you will be prompted for a Death
    Save. Roll manually or auto‑roll.
  - Check the Wounds & Debuffs section in your character sheet to track wounds
    and rest.

10.2 DM Quick Guide

  - Weather button (🌦️) in bottom toolbar → pick weather, adjust volume, apply
    lightning flashes.
  - Table background animations – drop a video file named table-texture.mp4 on
    the server and load the board.
  - Token Tray → Monster Browser, avatar change, size override.
  - Stamps: resizable slider, click to place.
  - Save Session persists everything.
  - Network Tuning panel for ping/timeout settings.
  - SRD Manager (/srd-manager) for homebrew content.
  - Use Hide tool (7) to pre‑place hidden traps/NPCs.
  - REQUEST CHECK sends skill/save DC to a player.
  - Undo/Redo with Ctrl+Z / Ctrl+Y or toolbar buttons.
  - View player sheets (👁️) → edit → “Save to Player”.
  - Use Spell FX tool to add visual flair to combat spells and abilities.
  - Use Shape Tool to mark persistent areas (walls, traps, etc.).
  - System Shock: Damage triggers will automatically prompt players/DM for CON
    saves and apply wounds; monitor wounds in character sheets.
